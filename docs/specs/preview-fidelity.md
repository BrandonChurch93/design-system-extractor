# Preview fidelity and sanitization

Stage `previews`. For each component, build a self-contained HTML and CSS preview from the extracted markup and matched CSS, render it, compare it to the captured crop, and decide `live` or `captured` (D-010). Every byte of this comes from an untrusted site, so sanitization is a hard requirement, not a nicety.

## Building the preview

For the component's first-seen instance (and each variant's representative instance):

1. **Markup.** `outerHTML` of the element, kept by capture (up to 300 KB), then sanitized (below). Images become placeholder blocks: a `span` with the image's rendered width and height, the image's own pixels cut from the page screenshot and stored beside the preview as its background over its average color (the average alone past 400 KB, D-098), `border-radius` copied, and `aria-hidden`. Inline `svg` is kept (sanitized). `iframe`, `video`, `canvas`, `object`, `embed` become placeholder blocks.
2. **CSS.** The matched rules for the element and every descendant, from the capture's matched-CSS map: each rule's selector list and declarations, in cascade order (origin, specificity, source order), with `!important` preserved. Rules keep each element's cascade order when merged and are used without their `@media` and `@supports` wrappers (they matched when the instance was captured). An `@container` condition on a container outside the component is read against the box that container had on the page: a rule whose condition held is kept bare, one whose condition failed is dropped, and a condition the builder cannot read (style queries, `or`, `not`) keeps its wrapper; a container inside the component answers its own queries (D-098). Rules whose selectors reference ancestors outside the element are rewritten to a scope class `.dse-root` that the preview wraps the markup in; id selectors follow the sanitizer's `dse-` prefix. Inherited properties that the element gets from ancestors (font-family, font-size, color, line-height, letter-spacing) are written onto `.dse-root` from the computed styles. CSS custom properties used by any kept declaration are resolved to their computed values on the element and declared on `.dse-root`. **Reset filtering (D-083).** Before the CSS is written: declarations whose value is `inherit`, `unset`, `initial`, `revert` or `revert-layer` are dropped; `box-sizing` and `-webkit-tap-highlight-color` declarations are dropped; rules whose selector list is only universal (`*`, `*::before`, `*::after`, `::before`, `::after`) are dropped, except that their `margin`, `padding` and `border` are carried onto the component's own tags that have a browser default for them (D-090); rules whose selectors are bare element names (`span`, `a`, `div, span`, `button`, `svg`) are kept only when a declaration survives the drops above and the element name appears in the component's markup; a reset value that overrides a browser default on a matched tag is kept even when it is a keyword (`a { color: inherit }`, `button { font: inherit }`), because dropping it would change the render (D-090); any rule with no declarations left is dropped. The preview shell sets `box-sizing` on the component's elements to the snapshot's majority value, so a component that depends on its box model renders as captured. The preview renders from the filtered CSS, so the upload-then-render check protects the filter: a component whose preview diverges because a reset mattered is `captured` with the `diff` reason, which is the correct outcome. The same filtered rules are the component's exported code (`exports-and-mcp.md`). `.dse-root` is a column flex container as wide as the instance with a transparent background (the frame paints the instance's `ground` behind it, Preview ground below; D-094), and the element keeps the exact box it had on the page (border-box, its measured width and height, no margin, no offsets if it was positioned) (D-053).
3. **Fonts.** For each family the component uses: if the site loads it from Google Fonts (a `fonts.googleapis.com` stylesheet link was observed), the preview gets the same `css2` link for that family and the weights used; else if the font file is same-origin or served with CORS and under 1 MB (300 KB before v1.2; a variable font is often larger, D-098), it is copied to storage and declared with `@font-face`; else the family name is kept and the fallback stack applies. Which case happened is recorded.
Before the CSS is written, the builder also takes the handling the P17 measurement named (Why previews fall back, measured): the causes it found and what the builder does for each are listed there.
4. **Shell.** `<!doctype html><html><head><meta charset="utf-8"><meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com {storagePublicBase}/; img-src data: {storagePublicBase}/"><style>html,body{margin:0;background:transparent}</style><link ...fonts><style>…rules…</style></head><body><div class="dse-root">…markup…</div></body></html>`.
5. **Store, then render check.** The preview document is uploaded to storage first (`components/{id}/preview.html`, and per variant `components/{id}/variants/{variantId}/preview.html`), and the render check loads it **from its storage URL**, exactly as the app will: a Playwright page navigates to that URL at the instance's width and height plus 16 px, DPR 2, paints the preview's `ground` on the page behind the transparent document (as the app's frame does), waits for fonts, screenshots the `.dse-root` box, and compares it to a crop of the page screenshot at the instance's exact box (a popup: the crop of the revealed element) with pixelmatch (threshold 0.1, anti-aliasing ignored), at the best alignment within 2 device pixels (found by descending from the unshifted position to the best neighbouring shift until none is better, D-066), forgiving a size difference of up to 4 device pixels. `diffPct` = differing pixels / total, any size difference beyond the slack counting as differing (D-053). Because the worker and the app load the same URL under the same document CSP, what the worker measured is what the visitor sees. Three render checks run at once, each on its own page, taking the next component in the order of render checks below; a component reached after the previews share of the run's time budget keeps its crop with `not-checked` (D-066).

**Order of render checks (D-095).** The previews stage builds and checks live previews for core components first, then page-specific components, by usage (instance count, most used first, then grid order) within each tier, so a run that reaches the previews share of its time budget has checked the components that matter; components past the cut keep their crops with `not-checked` as before. The three render lanes take the next component in that order.

Decision: `diffPct ≤ 2.5` → `mode: live`; otherwise `mode: captured` with `capturedReason: diff` (label `render differed by {pct} %`). Other captured reasons: `css-too-large` (label `styles too large`, the CSS cap), `fonts-unavailable` (label `fonts unavailable`, a required family could not be served and the fallback render differed even with text masked, below), `not-checked` (label `not checked in time`, the run reached the previews share of its time budget before this component's render check, D-066). The threshold is a constant in `pipeline/src/previews/constants.ts` and the panel shows the measured value.

**Fonts substituted (D-095).** When a family the component uses cannot be copied (step 3), the preview keeps the fallback stack and the render check runs the pixel comparison a second time with the text masked: the bounding boxes of the text nodes in the rendered preview, and the same boxes in the crop, are painted out in both images before pixelmatch. A component whose masked render matches is `live` with `fontsSubstituted` naming the families, and the panel's caption says the font was substituted; one that still differs is `captured` with `fonts-unavailable`. A component is never demoted for a font swap alone.

**Preview ground (D-094).** The frame's ground is the source element's effective background, recorded per instance as `ground` at capture time (`capture-and-states.md`, Ground). A preview takes the ground of the instance it was built from; the component's `ground` is the most common instance ground. The preview document leaves its background transparent and the app paints the ground behind it, live and captured alike, so a dark site's button sits on its own dark ground inside a light app with no halo; the render check paints the same ground behind the document before it screenshots, so the comparison measures what the app shows. The Ground toggle, on the card and in the panel (`components.md`, PreviewFrame and ComponentCard), swaps the painted ground for reading a light component against a dark ground and the reverse.

**Contrast fallback (D-109).** When the component's `fill` (`capture-and-states.md`, Ground) is within ΔE 5 (the pipeline's OKLab distance, `color/parse.ts`) of its `ground`, the card and the drawer paint the opposite tone instead: the app's `surface` for a dark ground, its `inverse-bg` for a light one (the toggle's Light and Dark grounds), and the caption reads `On a light ground: the site's ground matches the component.` (or `On a dark ground: …`). The Ground toggle's `Site` returns the sampled ground. A transparent component (`fill` null) keeps its sampled ground: it is its text and border that must be seen, and the sweep found none below 3.2:1 on the real sites. The render check still paints the sampled ground; the fallback is the app's choice of what to paint, not part of the live decision.

**Sizing (D-107).** A live preview renders at the component's captured size at the desktop viewport. On a card it is scaled down to fit its region, on width and on height, never up and never below 0.6×: a component that does not fit at 0.6× renders at 0.6× anchored to the region's top-left (`space-4` inset) and is clipped at the region's edge, with a 40 px fade into the ground on each clipped edge (a gradient from transparent to the painted ground, so the cut reads as a cut and not as the component's end). The scale caption reads `Shown at {scale}×` and, when clipped, `Shown at {scale}×, cut to fit`, so the reader knows a 44 px button is 44 px. In the drawer the preview renders at 1:1 and the stage scrolls horizontally when the preview is wider than it (a scrollbar in the app's `line` color, no caption), so the reader can see the whole component at its real size.

**State files (D-094).** For live components the worker writes one file per captured state beside the default, `preview-{state}.html` (and per variant), identical to `preview.html` plus the state's rules. The security posture does not change: frames stay `sandbox=""` with no scripts, served from the storage origin (D-017), so pins are done with files, not messages. Each state file is built so that, on load, the root element animates from the default values to the state values with the component's recorded transition timing: the delta's entries are written as one state rule on `.dse-root > :first-child` without `!important` (its specificity comes from that selector, so the animation can play over it), and the entries that carry a `transition` (D-088) are grouped by duration and easing into generated `@keyframes dse-state-{n}` blocks, from the default values to the state values, applied on the same selector with `animation: {duration} {easing} both`; an entry without a transition is applied at once by the state rule. Loading `preview-hover.html` shows the hover transition as the site plays it, and reloading replays it. Under `prefers-reduced-motion: reduce` a rule in the file sets `animation: none`, so the end values show at once. These generated blocks are the one exception to the rule that keyframes never reach a preview; a site's own keyframes still never do. Real pointer hover works inside a frame because CSS `:hover` needs no script and the default preview carries the state rules (below); pinning is for touch, for focus and for comparison. The app shows a state by pointing the frame at that file (the StateBar); no script, no query string, no class toggling. For captured components, state crops are shown.

**State rules in the default preview (D-106).** The default preview document carries the component's recorded state deltas as pseudo-class rules on its root, `.dse-root > :first-child:hover { … }`, `:focus-visible` from the `focus` delta, `:active` from the `active` delta, each with the recorded transition timing (the same values the state files write, D-088, D-094), through the same CSS sanitizer and the same `!important`-free rule as the state files. A state the component never captured writes no rule. The `open` and `disabled` states are not pseudo-classes and stay in their state files and the StateBar. The security suite covers the state rules as it covers the state files (no scripts, zero outbound requests, a value with `{`, `}` or `<` outside a quoted string refused). Frames stay `sandbox=""`: a click on an anchor inside the frame goes to `#` (relative `href` values are already rewritten) and a form cannot submit; a test clicks a link inside a card frame and asserts the frame's URL did not change.

## Why previews fall back, measured

Every run records the count of previews by mode and captured reason in `stats.previews` (`live`, `diff`, `css-too-large`, `fonts-unavailable`, `not-checked`; D-095), and the previews event states them. The baseline from the owner's two runs, before any change (the Partner, 2026-10-28):

| Run | live | diff | fonts-unavailable | not-checked | total |
| --- | --- | --- | --- | --- | --- |
| modernsoftworks.com (v1.1, visitor timeout) | 45 | 44 | 0 | 0 | 89 |
| linear.app (v1.0, visitor timeout) | 17 | 1 | 26 | 76 | 120 |

On modernsoftworks every fallback is a real render difference (median diff 2.5 %, at the threshold); on linear.app most are the budget. P17 measures three real sites (modernsoftworks.com, linear.app and stripe.com, the roster site with the weakest live rate in P16) at the showcase timeout, so `not-checked` measures the budget and not fidelity, and investigates every `captured` result by reason:

- `diff`: the storage render against the crop, classified by cause (a missing background image, a parent's background the element relied on, a pseudo-element, a font metric, an SVG icon with an external `use`, a CSS variable resolved on an ancestor outside the markup). Each cause found gets its handling in the builder (the opaque ancestor ground, inlined `use` references, pseudo-element rules, variables resolved on the element's ancestors).
- `fonts-unavailable`: the masked comparison above.
- `css-too-large`: the cap is measured after reset filtering; a cap that demotes a plain button is too low.
- `not-checked`: the previews share of the time budget ran out (D-066). Not a fidelity cause: the order of render checks decides which components are checked before the cut.

The measured causes, the handling added for each and the live rates before and after are recorded in D-098 (the build's P17 rulings) and in STATUS (`P17 real-site check`). Causes out of scope, which a captured preview may keep: a background video, a canvas, a third-party embed (D-095).

## Sanitization (hard rules)

Applied to markup before storage, with a whitelist sanitizer (DOMPurify in a jsdom context, with the configuration below), then a second pass of explicit checks. Nothing from a crawled site is stored or served unsanitized.

Markup:

- Remove: `script`, `noscript`, `template`, `iframe`, `frame`, `object`, `embed`, `applet`, `link`, `meta`, `base`, `form` is kept but its `action` and `method` removed, `input` kept with `name` removed and `type` limited to text-like types and `checkbox`, `radio`, `submit`, `button`, and `hidden`, which stays hidden (D-098).
- Remove every attribute starting with `on`, every `href` or `src` or `srcset` or `xlink:href` or `formaction` or `poster` that is not `https:` or a relative path or `data:image/`; `javascript:`, `vbscript:`, `data:text` are removed with the attribute. Relative `href` values are rewritten to `#` (previews never navigate). `target` removed. `style` attributes are kept but passed through the CSS sanitizer. `id` attributes are prefixed `dse-` to avoid clashing with the app. `class` kept. `data-*` kept except `data-dse-*` which is stripped.
- SVG: `script`, `foreignObject`, `use` with external href, `animate*`, `set` removed; `href` to external removed.

CSS (applied to every declaration in the preview stylesheet and every `style` attribute):

- Remove declarations containing `expression(`, `-moz-binding`, `behavior:`, `@import`, or `url(` whose target is not `https://fonts.gstatic.com`, `https://fonts.googleapis.com`, the storage public base, or `data:image/`.
- Remove `position: fixed` and `position: sticky` (they escape the preview box); convert to `relative`.
- Remove `@font-face` from site CSS; fonts come only from step 3 above.
- Allow `@media` and `@supports`. A site's `@keyframes` never reach a preview: the preview carries only the style rules matched to the component's elements (D-076). The one exception is the generated state blocks above (D-094).
- Cap total preview CSS at 200 KB, measured after filtering; over the cap the component is `captured` with reason `css-too-large` (label `styles too large`).

Serving:

- Previews are served from storage as files on the storage origin and rendered in the app only as `<iframe sandbox="" src="{storagePublicBase}/runs/{id}/components/{cid}/preview.html">` (no `allow-scripts`, no `allow-same-origin`). Never `srcdoc`: a `srcdoc` document inherits the embedding page's CSP, which would block the fonts the worker's render check loaded, and live decisions would be wrong. With `src` on the storage origin, the preview document's own `<meta>` CSP governs it, the same way in the worker and in the app. The iframe is sized to the preview's recorded dimensions; the app never reads into it.
- The S3 driver uploads `preview*.html` with `Content-Type: text/html; charset=utf-8` and every image with its image type. The sandbox attribute and the document's own CSP are the security boundary; no response header on the storage origin is relied upon.
- Every preview iframe carries `title="{component name} preview"` (axe requires a frame title) and `loading="lazy"` below the fold.
- The app's CSP is set by Next.js proxy (`apps/web/proxy.ts`, Next 16's name for middleware, D-058) with a per-request nonce: `default-src 'self'; script-src 'self' 'nonce-{nonce}'; style-src 'self' 'unsafe-inline'; img-src 'self' data: {storage}; font-src 'self'; connect-src 'self' {storage}; frame-src 'self' {storage}; frame-ancestors 'self'; base-uri 'self'; form-action 'self'`. `{storage}` is the origin of `STORAGE_PUBLIC_BASE_URL`; `'self'` in `frame-src` is for the catalog's 390 px demo frames (D-038). In development only, `script-src` also allows `'unsafe-eval'`, which the Next.js dev server needs; production never sends it (D-076). The nonce is passed to Next through the `x-nonce` request header so the App Router's inline scripts carry it. The `/open` route's header additionally allows `http://localhost:4300` in `frame-src` and `img-src`, a fixed value matching `dse serve`'s port.

## Security tests (part of every gate from P6 on)

A test suite of hostile component markup and CSS, each asserting the sanitized output and that rendering in the sandbox produces no network request outside the allowlist and executes no script:

- the same hostile values written as state deltas, which reach the default preview's `:hover`, `:focus-visible` and `:active` rules and the state files (D-106); a click on a link inside a card frame leaves the frame's URL unchanged.
- inline `onclick`, `onerror` on `img`, `javascript:` href, `srcdoc` iframe, `svg` with `script` and `foreignObject`, `style` with `expression()`, `url(javascript:…)`, `@import`, `position: fixed` overlay, a `form` with an external `action`, a `data:text/html` src, a `meta refresh`, a `base` tag, CSS custom property exfiltration via `url(var(--x))`, an `@font-face` pointing off-site.

Any new sanitizer bypass found later is added to this suite before it is fixed.

## Tests

- Live rates at the thresholds in `docs/evals.md`: at least 90% on clean and tailwind and 85% on css-in-js (D-095); at least 70% on each of the three real sites of the P17 check, counted over the components whose preview was checked.
- Render check order: core before page-specific, most instances first, in a unit test of the order function.
- The masked font comparison: a crafted component whose only difference is a substituted font is live with `fontsSubstituted`.
- The `messy-after` dark band: its rounded primary button on `#0B0D10` renders with no halo (QA screenshot at 2× zoom) and its ground is `#0B0D10`.
- Card previews take the pointer (D-106): hovering a card's frame on a fixture component with a recorded hover delta changes the computed style of the root inside the frame (read before and after, as the pin test does); `preview-frame.test.ts` still asserts `sandbox=""` with no flags.
- Sizing (D-107): a unit test on the scale function (the 0.6× floor, the top-left anchor, which edges clip); the card region stays 152 high.
- Contrast fallback (D-109): a unit test on the rule (ΔE just under and over 5, a transparent fill, a light ground).
- State files: pinning `Hover` loads the hover file, and its root reaches the recorded values after the recorded duration (a Playwright test reads the computed style inside the frame before and after); the security suite runs on the state files (still no scripts, still zero outbound requests).
- The messy fixture's deliberately unfaithful component (its CSS depends on a background image that sanitization strips) is `captured` with reason `render differed by {pct} %`; a unit test with 250 KB of matched CSS yields `styles too large`.
- A crafted component whose matched CSS includes a 7,000-character `unset` reset and three universal rules yields preview CSS under 1,500 characters that still renders within the pixel threshold.
- Fonts: the Google Fonts case is a unit test of the builder with an observed `fonts.googleapis.com` stylesheet link (no network); the same-origin copy case and the fallback case are exercised by the fixtures (self-hosted fonts).
- In the test environment the storage origin is MinIO; the render check and the app's iframe both load from it, so the test proves the two agree.
