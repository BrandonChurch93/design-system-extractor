How it works

Most of the pipeline is plain code. A model is used in two places, and only where judgment is needed: naming what a thing is, and writing the report. Everything measurable is measured.

The pipeline

1
CrawlHeadless Chromium opens the URL, reads sitemap.xml, header and footer navigation, and collects candidate pages. Cookie banners are dismissed, client-rendered apps are waited for.
Deterministic
2
Select pagesCandidates are scored for component coverage: pricing, forms, docs, lists, empty states. Pages sharing a template are folded to one. A short text-only model pass picks the final set, within the page cap.
Model · Haiku
3
CaptureEach page at 1440 and 390 px: DOM, computed styles for every element, screenshots. Controls are hovered, focused and tabbed through so states are captured, not guessed.
Deterministic
4
Cluster tokensRaw values become tokens: colors by ΔE, type by family, size, weight and line height, spacing by frequency against a base grid, radii and shadows by exact match. Usage is counted.
Deterministic
5
Detect componentsElements are fingerprinted by tag, class pattern, computed style and box ratio, then clustered. Each cluster gets a crop, its signature and its states.
Deterministic
6
Name and groupA model sees each cluster's crop and signature and answers one question: what is this, and which variants belong together. Batched per page, cached rubric, structured output.
Model · Haiku
7
Run checksContrast on real foreground and background pairs, focus visibility, tap target size at the mobile viewport, accessible names, reduced motion. Numbers, not opinions.
Deterministic
8
Compute driftNear-duplicate tokens, off-grid values, variants that differ by a pixel. A proposed clean set is derived that keeps every contrast ratio at or above the current one.
Deterministic
9
Write the report and exportsThe drift narrative, design-system.md and the prompt text are written from the computed facts. Token files and the MCP server are generated directly from the data.
Model · Sonnet

Cost and limits

A typical run costs well under a dollar. The site runs on a fixed daily budget and pauses when it is spent. Each visitor gets two runs a day and twelve pages per run.

Your own key lifts both limits and raises the page cap to forty. It stays in your browser and is sent only with your requests.

What the checks are, and are not

The five checks cover the parts of WCAG 2.2 that can be measured from a rendered page. They do not cover reading order, alternative text quality, keyboard traps, or anything that needs a human.

A component that passes every check is not "accessible". It has passed five measurements. The page says exactly which.
